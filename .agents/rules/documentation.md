# Documentation Rule

- Update documentation when a change makes existing instructions or contracts inaccurate.
- Prefer updating the existing canonical document over creating duplicate documentation.
- Keep implemented behavior distinct from proposed or planned behavior.
- Include prerequisites, commands, expected outcomes, and known limitations where useful.
- Do not claim that a feature is implemented merely because it appears in a plan.
